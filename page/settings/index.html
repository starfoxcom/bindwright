Every plugin setting

What the Bindwright plugin sets up, and the default it picks for each.

Once on your computer

Asked the first time. Change with /bindwright:setup global.

  • Code search

    findwright indexes every file the project tracks, code, docs and config alike, and answers plain questions, names and regex searches with short answers. It ships with Bindwright. none uses the built-in search: no index, and slower.

    Default findwright

  • Work language

    The language replies, commit messages and code comments come in, English or Spanish. The setup's own files stay in English: only the assistant reads them.

    Default English

  • Global instructions

    Working rules every project on your computer reads.

    Default Yes

  • Push guard

    Blocks force pushes in every repo on your computer.

    Default Yes

  • Session titles

    Names every session after its project and what it is working on.

    Default Yes

  • Builder agent

    A cheap Haiku helper writes the code, and the main model checks it.

    Default Yes

  • Code-style profile

    Learns how you write code from your repos, with your permission.

    Default Yes

  • Reply style

    Short, plain replies that are easy to follow (or at least it tries ;V): the answer first, and a follow-up question when it needs one. /output-style default turns it off.

    Default Yes

Mods

Add-ons that show live status in Claude Code. They need CLI 2.1.287 or later and Node.

  • ci-watch

    Watches pull request checks and wakes the session when they finish. After repeated red rounds, it holds changes until the session researches a better fix.

    Default On

  • compact-handoff

    Carries your words and a hand-off across compactions.

    Default On

  • mods

    A pane listing your mods and their commands.

    Default On

  • runners

    Shows your local CI runners, with start and stop buttons.

    Default Off

  • session-facts

    Tells the assistant the time, its context fill and your plan usage.

    Default On

  • session-info

    A row with the model, project, branch and changed files.

    Default On

  • shared-pc

    One session at a time runs heavy work, the rest wait in line.

    Default Off

  • skill-check

    Checks a skill ran every step it requires.

    Default On

  • tasks

    Keeps the task list honest and carries it across compactions.

    Default On

  • usage-guard

    Saves work near a plan limit and resumes after it resets.

    Default On

In every project

Asked in each project. Change with /bindwright:setup there.

  • Who works on it

    A team gets collaboration rules and a pre-commit hook.

    Default Just me

  • Whose project

    A client's or employer's gets a proprietary license.

    Default Mine

  • Public or private

    Whether the code is open to everyone on GitHub.

    Default Public if it's yours

  • AI credit in commits

    No AI co-author or generated-with lines, and a guard blocks them.

    Default Kept out

  • AI review

    An AI reviews every pull request before it merges.

    Default On

  • Deep review

    Risky changes get a second, deeper review.

    Default On

  • Code-size check

    Fails when code grows past the size limits.

    Default On

  • Plain-language writing

    Plain words that try to sound like you (it's still an AI writing them ;V).

    Default On

  • Visual changes in small steps

    Anything people see changes one checked step at a time.

    Default On

  • Where the code lives

    GitHub, GitHub with apps, Actions and boards blocked, just this computer, or another site. Blocked GitHub keeps pull requests and issues; just this computer needs no account; another site gets the GitHub parts to adapt.

    Default GitHub

  • Required reviewers

    Asked for a team project on GitHub. The people or teams each PR asks for review, and the merge waits for their approval.

    Default None

  • Local review before each merge

    Offered when GitHub can't run CI workflows, on hosted or local runners. Two fresh reviewers check each change before it merges, and nothing about them reaches GitHub.

    Default No

  • Assistant files on this computer only

    Asked for a client's or employer's project. CLAUDE.md, .claude/ and setup's own files stay out of every commit, listed in the clone's own ignore list.

    Default No

  • Where work is tracked

    A GitHub board, issues only, or a hand-off file in the repo.

    Default GitHub board

  • Private repo for work items

    Asked for public code, since its issues are public too.

    Default Yes

  • Board visibility

    The board holds every engineering detail. A clean public copy is optional.

    Default Private

Set for you

Not asked. Change in .bindwright/project.json, then run /bindwright:update.

  • Name, repo and license holder

    Read from the folder, its git remote and your git name.

    Default From the repo

  • License

    MIT for your own public project, Proprietary otherwise.

    Default MIT or Proprietary

  • Branching

    main for releases, develop for work.

    Default Gitflow

  • Merge style

    Each branch stays visible in the history.

    Default Merge commits

  • Pre-commit hook

    A team gets lefthook, which runs checks before each commit.

    Default Team only

  • Where the guards live

    In the repo, so everyone who clones it gets them.

    Default In the repo

  • Blocked commands

    Commands the assistant may never run.

    Default Standard

  • Architecture rule

    A folder layout to follow: clean, ddd, ecs, feature-based, hexagonal, layered or mvc.

    Default None

  • Confidentiality rule

    Added for someone else's private project.

    Default Client work only

  • Clean-room rule

    Keeps copied material out of a project based on an existing work.

    Default Off

  • Files the writing rule checks

    Which files the plain-language rule checks.

    Default The rule's list
