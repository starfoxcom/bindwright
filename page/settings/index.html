Every setting

Setup asks two kinds of questions. Choices for your computer are asked once and apply to every project on it. Project choices are asked in every project and apply to that repo only.

Once on your computer

Saved in ~/.claude/bindwright/settings.json. Change them with /bindwright:setup global.

  • Code-search tool

    How the assistant finds code in your projects. Setup installs the one you pick and indexes each project. Choices: tokensave, lsp-plugins, codegraph, serena, codebase-memory or none.

    tokensave (recommended)

  • Global instructions

    A short set of working rules every project on your computer reads, added to ~/.claude/CLAUDE.md.

    Yes (recommended)

  • Push guard for every project

    Blocks force pushes in every repo on your computer, including ones Bindwright never set up.

    Yes (recommended)

  • Builder agent

    A helper on the small, cheap Haiku model writes the code for a short brief, while the main model plans, runs the tests, reads the diff and commits. It costs a fraction of the main model doing the same work. Choosing no keeps all the work in the main session.

    Yes (recommended)

  • Code-style profile

    With your permission, reads code you wrote by hand, in local repos and your GitHub account, and saves a short profile of how you write. The weak spots are brought up to current practice, and every session follows it.

    Yes (recommended), now or later

Mods

Small add-ons for Claude Code that show live status and add commands. They need CLI 2.1.287 or later and Node, and you pick which ones to add.

  • ci-watch

    After a push, watches the pull request's checks and wakes the session once they have all settled.

    Optional

  • compact-handoff

    Turns compaction into a focused hand-off and adds a recall tool that searches the whole transcript afterwards.

    Optional

  • mods

    Opens a pane that lists every installed mod, what it does and the slash commands it adds.

    Optional

  • runners

    Shows one row per local CI runner you list, whether it is running and when its next run is due, with start and stop buttons.

    Optional

  • session-facts

    Tells the assistant the time, how full its context is and your plan usage on every prompt, and shows you the same in a row above the prompt.

    Recommended

  • session-info

    Adds one row above the prompt with the model, the project, the git branch and the changed files.

    Optional

  • shared-pc

    Lets one session at a time hold the computer for heavy work like builds and full test suites; the rest wait in a visible line.

    Optional

  • skill-check

    Checks that a skill ran every step its contract requires, and asks for the ones it missed.

    Optional

  • tasks

    Keeps the task list honest: one task in progress, a list that survives compaction, and a nudge to carry on when work is left.

    Optional

  • usage-guard

    Near a plan limit, has every session save its work, then resumes them after the limit resets.

    Optional

In every project

Saved in .bindwright/project.json in the repo. Run /bindwright:setup again in that project to change them.

  • Who works on it

    Just you, or a team. A team gets the collaboration rules and a pre-commit hook.

    Just me

  • Whose project it is

    Yours, or someone else's, such as a client's or an employer's. Someone else's gets a proprietary license and, when private, a confidentiality rule.

    Mine

  • Private or public

    Whether the code is open to everyone on GitHub or kept private to you and your team.

    Public for your own project, private for someone else's

  • AI credit in commits

    Kept out means commits, PRs and comments carry no generated-with lines or AI co-author credit, and a guard blocks them.

    Kept out

  • AI review on every pull request

    An AI reviewer checks every pull request before it merges.

    On

  • Deeper review on risky changes

    Changes that touch risky code, such as security or saved data, get a second, deeper review. Needs the AI review.

    On

  • Code-size check

    A check that fails when code grows past the size limits.

    On

  • Plain-language writing

    Replies, docs and commit text in plain words that try to sound like you wrote them (it's still an AI writing them ;V).

    On

  • Visual changes in small steps

    Changes to anything people see are made in small steps, each checked before the next.

    On

  • Where the work state lives

    A GitHub board with the issues plus a short hand-off note, GitHub issues only, or a detailed hand-off file in the repo.

    GitHub board and a short hand-off note

  • Private repo for work items

    Asked only when the code is public, since a public repo's issues are public too. Keeps the work items in a private repo.

    Yes (recommended)

  • Board visibility

    The board holds the full engineering details and stays private. A clean public copy for outsiders is optional, and making the full board public gets a clear warning first.

    Private

Not asked, with a default

Set from your answers or left at a default. Change them in .bindwright/project.json, then run /bindwright:update.

  • Project name, repo address and license holder

    Read from the repo folder, its git remote and your git name.

    Read from the repo

  • License

    Picked from your answers: MIT for your own public project, Proprietary otherwise.

    MIT or Proprietary

  • Branching

    Gitflow: main for releases and develop for work. main stays the default branch on GitHub.

    Gitflow

  • Merge style

    Every pull request merges with a merge commit, so each branch stays visible in the history.

    Merge commits

  • Pre-commit hook

    None alone. A team gets lefthook, which runs checks before each commit.

    None alone, lefthook for a team

  • Where the guards live

    In the repo, so everyone who clones it gets them. The other choice puts them only in each person's ~/.claude.

    In the repo

  • Blocked commands

    The standard list of commands the assistant may never run.

    Standard

  • Architecture rule

    An optional folder layout the assistant follows: none, clean, ddd, ecs, feature-based, hexagonal, layered or mvc.

    None

  • Confidentiality rule

    Added for someone else's private project, where the assistant follows a confidentiality rule.

    On for someone else's private project

  • Clean-room rule

    For projects derived from an existing work. It keeps what ships free of copied material.

    Off

  • Files the writing rule checks

    The files the plain-language writing rule checks. Setup uses the rule's own list.

    The rule's own list
