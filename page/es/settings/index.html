Cada ajuste

La instalación hace dos tipos de preguntas. Las opciones de tu computadora se preguntan una vez y valen para todos los proyectos de tu computadora. Las opciones del proyecto se preguntan en cada proyecto y solo aplican a ese repo.

Una vez en tu computadora

Se guarda en ~/.claude/bindwright/settings.json. Cámbialas con /bindwright:setup global.

  • Herramienta de búsqueda de código

    Cómo encuentra el asistente el código de tus proyectos. La instalación instala la que elijas e indexa cada proyecto. Opciones: tokensave, lsp-plugins, codegraph, serena, codebase-memory o none.

    tokensave (recomendado)

  • Instrucciones globales

    Un conjunto corto de reglas de trabajo que lee cada proyecto de tu computadora, agregado a ~/.claude/CLAUDE.md.

    Sí (recomendado)

  • Guardia de push en todos los proyectos

    Bloquea los force push en cada repo de tu computadora, incluso en los que Bindwright nunca configuró.

    Sí (recomendado)

  • Agente constructor

    Un ayudante con el modelo Haiku, pequeño y barato, escribe el código a partir de una instrucción corta, mientras el modelo principal planea, corre las pruebas, revisa el diff y hace los commits. Cuesta una fracción de lo que costaría que el modelo principal haga el mismo trabajo. Si eliges no, todo el trabajo se queda en la sesión principal.

    Sí (recomendado)

  • Perfil de estilo de código

    Con tu permiso, lee el código que escribiste a mano, en repos locales y en tu cuenta de GitHub, y guarda un perfil corto de cómo escribes. Los puntos débiles se llevan a la práctica actual, y cada sesión lo sigue.

    Sí (recomendado), ahora o después

Mods

Pequeños complementos para Claude Code que muestran el estado en vivo y agregan comandos. Necesitan CLI 2.1.287 o más reciente y Node, y tú eliges cuáles agregar.

  • ci-watch

    Después de un push, vigila las revisiones del pull request y despierta la sesión cuando todas terminan.

    Opcional

  • compact-handoff

    Convierte la compactación en un traspaso enfocado y agrega una herramienta de recuperación que busca en toda la transcripción después.

    Opcional

  • mods

    Abre un panel con cada mod instalado, qué hace y los comandos que agrega.

    Opcional

  • runners

    Muestra una fila por cada runner de CI local que listes: si está corriendo, cuándo es su siguiente corrida, con botones de iniciar y detener.

    Opcional

  • session-facts

    Le dice al asistente la hora, qué tan lleno está su contexto y el uso de tu plan en cada prompt, y te muestra lo mismo en una fila sobre el prompt.

    Recomendado

  • session-info

    Agrega una fila sobre el prompt con el modelo, el proyecto, la rama de git y los archivos cambiados.

    Opcional

  • shared-pc

    Deja que una sesión a la vez tenga la computadora para trabajo pesado, como compilaciones y suites de pruebas completas; las demás esperan en una fila visible.

    Opcional

  • skill-check

    Revisa que una habilidad haya corrido cada paso que exige su contrato, y pide los que se saltó.

    Opcional

  • tasks

    Mantiene la lista de tareas honesta: una tarea en progreso, una lista que sobrevive a la compactación y un recordatorio para seguir cuando queda trabajo.

    Opcional

  • usage-guard

    Cerca de un límite del plan, hace que cada sesión guarde su trabajo y luego las reanuda cuando el límite se reinicia.

    Opcional

En cada proyecto

Se guarda en .bindwright/project.json del repo. Vuelve a correr /bindwright:setup en ese proyecto para cambiarlas.

  • Quién trabaja en él

    Solo tú, o un equipo. Un equipo recibe las reglas de colaboración y un hook de pre-commit.

    Solo yo

  • De quién es el proyecto

    Tuyo, o de alguien más, como un cliente o un empleador. Si es de alguien más, recibe una licencia propietaria y, si es privado, una regla de confidencialidad.

    Mío

  • Privado o público

    Si el código está abierto a todos en GitHub o es privado para ti y tu equipo.

    Público para el tuyo, privado para el de alguien más

  • Crédito de la IA en los commits

    Quedar fuera significa que los commits, pull requests y comentarios no llevan líneas de 'generado con' ni crédito de coautor de la IA, y una guardia lo bloquea.

    Fuera

  • Revisión con IA en cada pull request

    Un revisor de IA revisa cada pull request antes de integrarse.

    Activada

  • Revisión más profunda en cambios riesgosos

    Los cambios que tocan código riesgoso, como seguridad o datos guardados, reciben una segunda revisión más a fondo. Necesita la revisión con IA.

    Activada

  • Revisión de tamaño del código

    Una revisión que falla cuando el código crece más allá de los límites de tamaño.

    Activada

  • Escritura en lenguaje claro

    Respuestas, docs y texto de commits en palabras sencillas que intentan sonar como si lo hubieras escrito tú (sigue siendo una IA la que lo escribe ;V).

    Activada

  • Cambios visuales en pasos chicos

    Los cambios a lo que la gente ve se hacen en pasos chicos, y cada uno se revisa antes del siguiente.

    Activada

  • Dónde vive el estado del trabajo

    Un tablero de GitHub con los issues y una nota corta de traspaso, solo issues de GitHub, o un archivo de traspaso detallado en el repo.

    Tablero de GitHub y una nota corta de traspaso

  • Repo privado para los pendientes

    Solo se pregunta cuando el código es público, porque los issues de un repo público también son públicos. Guarda los pendientes en un repo privado.

    Sí (recomendado)

  • Visibilidad del tablero

    El tablero tiene todos los detalles de ingeniería y se queda privado. Una copia pública limpia para gente de fuera es opcional, y hacer público el tablero completo muestra antes una advertencia clara.

    Privado

No se pregunta, trae un valor por defecto

Salen de tus respuestas o quedan en un valor por defecto. Cámbialas en .bindwright/project.json y luego corre /bindwright:update.

  • Nombre del proyecto, dirección del repo y titular de la licencia

    Se leen de la carpeta del repo, su remoto de git y tu nombre en git.

    Se lee del repo

  • Licencia

    Sale de tus respuestas: MIT para tu proyecto público, propietaria en otro caso.

    MIT o propietaria

  • Ramas

    Gitflow: main para las versiones y develop para el trabajo. main sigue siendo la rama predeterminada en GitHub.

    Gitflow

  • Estilo de merge

    Cada pull request se integra con un commit de merge, así cada rama sigue visible en el historial.

    Commits de merge

  • Hook de pre-commit

    Ninguno solo. Un equipo recibe lefthook, que corre revisiones antes de cada commit.

    Ninguno solo, lefthook para un equipo

  • Dónde viven las guardias

    En el repo, así todo el que lo clone las recibe. La otra opción las pone solo en el ~/.claude de cada persona.

    En el repo

  • Comandos bloqueados

    La lista estándar de comandos que el asistente nunca puede correr.

    Estándar

  • Regla de arquitectura

    Una estructura de carpetas opcional que sigue el asistente: none, clean, ddd, ecs, feature-based, hexagonal, layered o mvc.

    Ninguna

  • Regla de confidencialidad

    Se agrega para un proyecto privado de alguien más, donde el asistente sigue una regla de confidencialidad.

    Activada para un proyecto privado de alguien más

  • Regla de clean room

    Para proyectos derivados de un trabajo existente. Mantiene limpio lo que se entrega, sin material copiado.

    Desactivada

  • Archivos que revisa la regla de escritura

    Los archivos que revisa la regla de escritura en lenguaje claro. La instalación usa la lista propia de la regla.

    La lista de la regla
